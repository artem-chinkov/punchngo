# PUNCH 'N' GO
## Game Design Document — v1.0

**Жанр:** First-Person Arcade Beat 'em Up  
**Платформа:** Mobile Web (Portrait Only)  
**Движок:** Phaser 4  
**Стек:** TypeScript + Vite  
**Графика:** современный детализированный пиксель-арт, псевдо-3D  
**Первый уровень:** Park — «Парк»  
**Статус:** утверждённая концепция, подготовка к техническому прототипу  
**Дата:** 7 ноября 2026 года

---

# 1. Концепция игры

PUNCH 'N' GO — мобильный аркадный файтинг от первого лица, сочетающий динамику классических beat 'em up с псевдотрёхмерной перспективой ретрогонок SEGA.

Игрок автоматически движется вперёд по извилистой дорожке городского парка. Навстречу выходят группы уличных хулиганов.

При приближении противников герой останавливается. Игрок побеждает их с помощью ударов кулаками, блоков и своевременных контратак. После победы движение возобновляется.

Главная особенность — полноценная аркадная боевая система, управляемая одним пальцем.

## Основные принципы

- Простое управление, но требующее мастерства.
- Быстрые и зрелищные рукопашные схватки.
- Важность правильной дистанции и тайминга.
- Управление выносливостью.
- Поощрение длинных комбо и контратак.
- Постепенное увеличение сложности.
- Короткие игровые сессии и возможность улучшать рекорд.

## Первая версия

Один законченный уровень продолжительностью ориентировочно 2–3 минуты при успешном прохождении.

Содержит 10 боевых столкновений и отдельную финальную схватку с мини-боссом.

В первой версии предусмотрена одна сбалансированная сложность.

# 2. Управление

Игра рассчитана исключительно на вертикальную ориентацию смартфона.

Управление осуществляется касаниями в любом месте активного игрового экрана, кроме интерактивных элементов меню.

| Действие | Управление |
|---|---|
| Обычный удар | Короткий тап |
| Следующий удар | Повторный тап |
| Блок | Удержание пальца |
| Контратака | Тап в подходящий момент |
| Движение | Автоматическое |
| Выбор цели | Автоматический |

## 2.1. Распознавание жестов

Предварительный порог удержания — 180 мс.

- Быстрое отпускание пальца запускает удар.
- При удержании дольше порога включается блок.
- При отпускании блока герой возвращается в боевую стойку.
- Отпускание после блока не должно запускать дополнительный удар.

Точный порог необходимо настроить при тестировании на смартфоне.

Отдельные виртуальные кнопки атаки и защиты отсутствуют.

# 3. Передвижение и игровой мир

## 3.1. Автоматическое движение

Герой самостоятельно движется вперёд по дорожке.

Игрок не управляет направлением движения.

При достижении боевой зоны герой останавливается, а враги продолжают сближаться до начала рукопашной схватки.

После победы над всей группой движение автоматически возобновляется.

## 3.2. Псевдо-3D

Используется технология, напоминающая классические гонки SEGA Mega Drive, включая OutRun-подобные эффекты перспективы.

Мир строится из следующих элементов:

- Перспективная дорожка, состоящая из сегментов.
- Плавные горизонтальные изгибы дорожки.
- Многослойный дальний фон.
- Масштабируемые спрайты деревьев, кустов, лавок и фонарей.
- Персонажи, масштабируемые в зависимости от расстояния до камеры.
- Независимые слои кулаков героя и HUD.

Дорожка визуально расширяется по мере приближения к камере.

Объекты окружения увеличиваются и перемещаются к краям экрана по законам перспективной проекции.

## 3.3. Камера

Вид строго от первого лица.

Допускаются:

- Лёгкое покачивание при ходьбе.
- Небольшое смещение к выбранной цели.
- Короткая тряска при сильных попаданиях.
- Незначительное замедление при особо мощных ударах.

Полноценное свободное вращение камеры отсутствует.

# 4. Боевая система

## 4.1. Общие правила

Герой атакует противников кулаками, поочерёдно используя левую и правую руку.

Удар выполняется только при наличии достаточной выносливости.

Попадание зависит от расстояния до противника и его положения в зоне удара.

Обычный удар расходует выносливость даже при промахе.

Предваральный интервал между ударами — 0,28 секунды.

## 4.2. Трёхударная комбинация

Базовая последовательность:

1. Левый прямой удар.
2. Правый прямой удар.
3. Усиленный удар.

После третьего удара комбинация повторяется с сохранением естественного чередования рук.

| Удар | Урон | Выносливость |
|---|---:|---:|
| Первый | 100% | 12 |
| Второй | 100% | 12 |
| Третий | 150% | 18 |

Для продолжения короткой комбинации следующий успешный удар должен произойти в пределах 1,2 секунды.

Промах сбрасывает последовательность.

Блок также прерывает короткую комбинацию.

## 4.3. Усиленный третий удар

Третий удар выполняется как широкий хук.

Эффекты:

- Основная цель получает 150% стандартного урона.
- До двух близко расположенных соседних врагов получают 25% стандартного урона.
- Основной противник заметно отшатывается.
- Соседние противники кратковременно теряют равновесие.
- Обычные атаки задетых противников могут прерываться.

Зона поражения представляет собой ограниченный сектор перед игроком.

Массового оглушения соседних врагов не происходит.

За один усиленный удар счётчик длинного комбо увеличивается только на единицу, независимо от количества задетых противников.

---

# 5. Система выносливости

Шкала выносливости постоянно отображается в нижней части экрана.

Максимальное значение — 100 единиц.

## Предварительные параметры

| Событие | Изменение |
|---|---:|
| Обычный удар | −12 |
| Усиленный удар | −18 |
| Удержание блока | −6/сек. |
| Блок обычного удара | −15 |
| Блок сильного удара | −30 |
| Успешная контратака | +8 |
| Успешное попадание при комбо 5+ | +3 |
| Восстановление вне боя | +20/сек. |
| Базовое восстановление в бою | +5/сек. |

Восстановление в бою приостанавливается во время активной анимации удара и удержания блока. Это предварительное правило для балансировки.

При недостаточной выносливости атака не выполняется.

Если выносливость заканчивается во время блока, происходит пробитие защиты.

## Пробитие защиты

- Герой временно теряет равновесие.
- Примерная длительность уязвимости — 1 секунда.
- Кулаки опускаются.
- Шкала выносливости мигает красным.

---

# 6. Блок и контратаки

## 6.1. Блок

Удержание пальца заставляет героя поднять оба кулака перед собой.

Блок предотвращает потерю здоровья от обычных блокируемых атак, но расходует выносливость.

Успешный блок не сбрасывает длинное комбо.

Блок не может продолжаться бесконечно из-за расхода выносливости.

## 6.2. Контратака

Контратака выполняется своевременным ударом в момент подготовки вражеской атаки.

### Визуальные сигналы

- Красный восклицательный знак — враг готовится атаковать.
- Жёлтая вспышка — открыто окно контратаки.
- Успешный тап — контратака.

### Эффекты успешной контратаки

- Атака противника прерывается.
- Противник оглушается примерно на 1 секунду.
- Следующий удар по этому противнику получает +50% урона.
- Выносливость героя восстанавливается на 8 единиц.
- Начисляются дополнительные очки.
- Комбо продолжается.

Бонус усиленного удара не переносится автоматически на другого противника.

### Предварительные параметры

| Параметр | Значение |
|---|---:|
| Подготовка обычной вражеской атаки | 0,9 сек. |
| Окно контратаки | 0,35 сек. |
| Оглушение | 1 сек. |
| Бонус следующего удара | +50% |
| Бонус к выносливости | +8 |

Все интервалы доступны для балансировки.

---

# 7. Автоматический выбор цели

Игрок не выбирает цель вручную.

Приоритеты автонаведения:

1. Доступный для удара противник в активном окне контратаки.
2. Текущий противник, по которому уже ведётся серия ударов.
3. Ближайший доступный противник.

После поражения текущего врага выбирается следующий.

При успешном попадании цель ненадолго фиксируется, чтобы предотвращать хаотическое переключение.

Кулаки могут слегка менять направление удара в сторону выбранного врага.

Во время группового боя персонажи остаются перед камерой.

---

# 8. Промахи и длинное комбо

## 8.1. Промах

Удар считается промахом, если:

- Противник находится вне дистанции поражения.
- Противник успел сместиться за пределы зоны удара.
- Игрок атаковал слишком рано.

Последствия промаха:

- Расход выносливости.
- Сброс короткой трёхударной комбинации.
- Сброс длинного комбо.

### Защита от несправедливого сброса

После принудительного отступления врага действует предварительное защитное окно 0,35 секунды.

Промах в этот период расходует выносливость и прерывает короткую комбинацию, но не обнуляет длинное комбо.

## 8.2. Длинное комбо

За каждую успешную атаку игрока добавляется +1 к комбо.

Счётчик комбо:

- Сбрасывается при обычном промахе.
- Сбрасывается при получении урона.
- Сохраняется при успешном блоке.
- Продолжается при контратаке.
- Приостанавливается во время автоматического перехода между группами.

Предварительное время поддержания серии — 2 секунды.

Во время блокирования комбо не должно сохраняться бесконечно: таймер может приостанавливаться только в пределах периода вражеской атаки.

## 8.3. Множители очков

| Комбо | Множитель |
|---|---:|
| 1–2 | ×1 |
| 3–4 | ×1,5 |
| 5–9 | ×2 |
| 10+ | ×3 |

Множитель применяется к очкам за побеждённых врагов.

Визуальные эффекты увеличиваются с ростом комбо.

# 9. Противники

В первом уровне используются три основных типа обычных врагов.

## 9.1. Обычный хулиган

- Средняя скорость.
- Средний запас здоровья.
- Предсказуемые прямые удары.
- Примерно 2–3 обычных успешных попадания для победы.

Роль: основной противник, обучение базовым механикам.

## 9.2. Быстрый хулиган

- Высокая скорость.
- Небольшой запас здоровья.
- Активное перемещение в стороны.
- Быстрая подготовка атак.
- Возможность короткого рывка вперёд.

Роль: проверка реакции игрока.

## 9.3. Громила

- Низкая скорость перемещения.
- Высокий запас здоровья.
- Примерно 5–6 обычных ударов для победы.
- Медленные, но сильные атаки.
- Высокая стоимость блокирования его ударов.

Роль: проверка управления выносливостью.

## 9.4. Групповой AI

Одновременно на экране могут находиться 2–3 противника.

Враги:

- Занимают левую, центральную и правую зоны.
- Свободно перемещаются между зонами.
- Могут отступать и наступать.
- Занимают свободные позиции после поражения других.
- Не заходят за спину игроку.
- Не покидают основное поле зрения.

Для справедливости боя применяется система очередности атак.

Только один обычный противник одновременно может выполнять полноценную результативную атаку.

Остальные могут перемещаться, угрожать и ожидать очереди.

Приоритеты выбора атакующего и интервалы между атаками настраиваются через параметры AI.

## 9.5. Полоски здоровья

У обычных противников здоровье отображается только после получения урона.

Полоска появляется над врагом и исчезает через 1,5 секунды после последнего попадания.

Каждое новое попадание обновляет таймер.

У мини-босса шкала здоровья отображается постоянно.

# 10. Первый уровень — PARK

## 10.1. Общая структура

Первый уровень состоит из трёх участков.

Контрольные точки находятся примерно на 33% и 66% пути.

Предусмотрено 10 фиксированных столкновений и отдельный бой с мини-боссом.

Состав и последовательность групп не меняются при повторных прохождениях.

## Участок 1 — Начало парка

| № | Враги | Основная задача |
|---|---|---|
| 1 | Обычный хулиган | Обучение ударам |
| 2 | Быстрый хулиган | Блок и контратака |
| 3 | Два обычных | Автонаведение и групповая схватка |

После участка: первая контрольная точка, восстановление 30% максимального здоровья.

## Участок 2 — Аллея

| № | Враги | Основная задача |
|---|---|---|
| 4 | Обычный + быстрый | Переключение целей |
| 5 | Два быстрых | Реакция и защита |
| 6 | Два обычных + быстрый | Комбо и усиленный удар |

После участка: вторая контрольная точка, восстановление 30% максимального здоровья.

## Участок 3 — Дальняя часть парка

| № | Враги | Основная задача |
|---|---|---|
| 7 | Громила + обычный | Мощные удары |
| 8 | Громила + быстрый | Выносливость |
| 9 | Обычный + два быстрых | Контратаки в группе |
| 10 | Громила + быстрый + обычный | Финальная проверка группового боя |

После десятой группы герой достигает отдельной контрольной точки перед мини-боссом.

Всего: 21 обычный противник.

## 10.2. Ритм уровня

Между столкновениями присутствуют короткие участки автоматического движения.

Ориентировочный ритм:

- Движение: 3–5 секунд.
- Сближение: 2–3 секунды.
- Бой: 5–12 секунд, зависит от группы и игрока.
- Переход: 1–2 секунды.

Продолжительность уровня уточняется после проверки реального игрового процесса.

# 11. Мини-босс — БУЛЬДОГ

Финальный противник первого уровня.

Крупный уличный громила с оригинальной внешностью, отдельными анимациями и увеличенным запасом здоровья.

## 11.1. Появление

Игрок достигает финальной площадки парка.

Движение прекращается.

Бульдог появляется на расстоянии, медленно приближается, разминает кулаки и занимает боевую стойку.

На экране появляется его постоянная шкала здоровья.

## 11.2. Атаки

**Прямой удар**

Стандартная атака с читаемым замахом. Доступны блок и контратака.

**Мощный удар**

Медленная атака с повышенным уроном и высокой стоимостью блокирования.

**Двойная атака**

Два последовательных удара. Игрок может заблокировать оба либо прервать комбинацию своевременной контратакой.

Неблокируемых атак в первой версии нет.

## 11.3. Фазы

**Фаза 1: 100–50% HP**

- Относительно медленные атаки.
- Длинные паузы.
- Понятные сигналы контратаки.

**Фаза 2: ниже 50% HP**

- Повышенная частота атак.
- Сокращённые паузы.
- Использование двойной атаки.
- Изменённая стойка и выражение лица.

Ориентировочная продолжительность схватки: 30–45 секунд.

## 11.4. Автоматическое добивание

При последнем успешном ударе:

1. Здоровье босса достигает нуля.
2. Время кратковременно замедляется.
3. Кулак наносит мощный завершающий удар.
4. Возникает пиксельная вспышка.
5. Камера кратковременно вздрагивает.
6. Босс отлетает назад, уменьшаясь в перспективе.
7. Появляется экран завершения уровня.

Продолжительность последовательности — примерно 2–3 секунды.

Дополнительные действия игрока не требуются.

# 12. Здоровье и контрольные точки

## 12.1. Здоровье героя

Здоровье отображается в верхнем HUD с помощью портрета героя.

Портрет меняет выражение лица при снижении здоровья по принципу, напоминающему классическую DOOM.

Все изображения портрета создаются специально для PUNCH 'N' GO.

## 12.2. Восстановление

На контрольных точках между участками восстанавливается 30% максимального здоровья.

Восстановление ограничено максимальным запасом HP.

Во время обычных боёв здоровье не восстанавливается.

При первом достижении мини-босса здоровье и выносливость полностью восстанавливаются.

Это предотвращает ситуацию, когда намеренное поражение становится выгоднее продолжения боя.

## 12.3. Поражение

При нулевом здоровье появляется экран поражения.

Игрок может продолжить с последней достигнутой контрольной точки.

После возрождения:

- Здоровье полностью восстановлено.
- Выносливость полностью восстановлена.
- Комбо обнулено.
- Прогресс возвращается к контрольной точке.
- Текущий счёт уменьшается на 20%.

Поражение от мини-босса возвращает игрока непосредственно к началу битвы с ним.

Третий участок повторно проходить не нужно.

Контрольные точки не должны выдавать бонус лечения повторно при циклических возрождениях сверх уже описанного полного восстановления после поражения.

## 12.4. Защита от повторного начисления очков

Каждый конкретный противник приносит награду за победу не более одного раза за один забег.

При повторном прохождении группы после поражения ранее полученные награды не начисляются заново.

Состояние наград необходимо учитывать отдельно от состояния возрождённых противников.

# 13. Очки и рейтинг

## 13.1. Базовые награды

| Действие | Очки |
|---|---:|
| Победа над обычным хулиганом | 100 |
| Победа над быстрым хулиганом | 150 |
| Победа над громилой | 250 |
| Победа над Бульдогом | 1 000 |
| Успешная контратака | 50 |
| Завершение уровня | 500 |

Награды за побеждённых врагов умножаются на текущий множитель длинного комбо.

Бонус за контратаку учитывается отдельно.

Все значения предварительные.

## 13.2. Рейтинг

Ранг зависит исключительно от итогового счёта.

| Ранг | Очки |
|---|---:|
| S | 10 000+ |
| A | 7 500–9 999 |
| B | 5 000–7 499 |
| C | 0–4 999 |

Пороги подлежат пересмотру после тестирования реального диапазона результатов.

Пропущенные удары и время прохождения не входят в формулу рейтинга напрямую.

## 13.3. Экран результатов

После завершения уровня отображаются:

- Итоговые очки.
- Ранг S/A/B/C.
- Побеждённые противники.
- Максимальное комбо.
- Успешные контратаки.
- Полученные удары.
- Количество поражений.
- Лучший предыдущий результат.

Рекорды сохраняются локально в браузере.

Для первого прототипа серверная таблица лидеров не требуется.

# 14. Обучение

Обучение интегрировано непосредственно в первый уровень.

Отдельного тренировочного режима нет.

## Первое столкновение

Подсказка: **«ТАПАЙ, ЧТОБЫ БИТЬ!»**

Игрок осваивает обычные удары и их последовательность.

## Второе столкновение

Подсказка: **«УДЕРЖИВАЙ — БЛОК!»**

При подготовке атаки появляется объяснение контратаки:

**«ЖЁЛТЫЙ СИГНАЛ — БЕЙ!»**

В первой обучающей ситуации допускается кратковременное замедление времени.

## Третье столкновение

Подсказка: **«СОБИРАЙ КОМБО!»**

Игрок знакомится с групповыми схватками, автонаведением и выносливостью.

После обучения подсказки скрываются.

При повторном прохождении обучение автоматически отключается.

# 15. Интерфейс — HUD

HUD проектируется специально для вертикального экрана смартфона.

## 15.1. Верхняя панель

Три горизонтально расположенных блока:

**Слева — здоровье**

- Портрет героя.
- Изменение выражения лица по мере получения урона.
- Числовое либо компактное визуальное отображение оставшегося HP.

**По центру — прогресс уровня**

- Горизонтальная шкала.
- Пройденная дистанция.
- Остаток пути.
- Отметки контрольных точек.

Прогресс определяется расстоянием в игровом мире, а не временем.

**Справа — очки**

- Текущий счёт.
- Краткая анимация увеличения очков.

## 15.2. Нижняя часть

- Кулаки героя.
- Постоянная шкала выносливости.
- Три небольших индикатора короткой комбинации.

Все элементы должны учитывать безопасные области экрана телефона.

## 15.3. Центральная часть

Контекстные элементы:

- Увеличивающийся счётчик комбо.
- `COUNTER!`
- `MISS!`
- Временные полоски HP противников.
- Красные/жёлтые предупреждения об атаке.
- Временные сообщения обучения.

Интерфейс не должен закрывать лицо атакующего врага и область его замаха.

## 15.4. Мини-босс

Во время боя дополнительно отображается постоянная шкала здоровья Бульдога.

# 16. Визуальный стиль и ассеты

## 16.1. Общий стиль

Современный детализированный пиксель-арт с визуальными отсылками к 16-битным аркадам SEGA.

Референс по характеру персонажей и насыщенности графики — Streets of Rage 2.

Референс по перспективе и движению мира — классические псевдо-3D гонки.

При этом все персонажи, фоны, графические элементы и интерфейс должны быть оригинальными.

## 16.2. Противники

Необходимы оригинальные спрайты:

1. Обычный хулиган.
2. Быстрый хулиган.
3. Громила.
4. Мини-босс Бульдог.

Для каждого типа предусматриваются:

- Ожидание.
- Приближение.
- Боевая стойка.
- Подготовка атаки.
- Атака.
- Получение урона.
- Отшатывание.
- Оглушение.
- Поражение.

Мини-босс дополнительно требует состояний второй фазы и финального отбрасывания.

## 16.3. Руки героя

Отдельные спрайты левой и правой руки:

- Нейтральная стойка.
- Обычный удар.
- Усиленный удар.
- Блок.
- Получение удара.
- Анимация восстановления после удара.
- Анимация добивания.

Кулаки всегда находятся на переднем плане.

## 16.4. Окружение

Необходимы:

- Панорама неба.
- Дальний городской фон.
- Дальние деревья.
- Текстуры и детали дорожки.
- Большие и маленькие деревья.
- Кусты.
- Парковые лавочки.
- Фонари.
- Мелкие декоративные объекты.

Деревья, лавочки и фонари выполняются отдельными спрайтами, чтобы масштабироваться по перспективе.

## 16.5. HUD и эффекты

Необходимы:

- Портрет героя в нескольких состояниях здоровья.
- Рамки и фоны HUD.
- Шкала прогресса.
- Шкала выносливости.
- Полоски здоровья врагов.
- Полоска босса.
- Счётчик очков.
- Индикатор трёх ударов.
- Надписи комбо.
- Красный и жёлтый сигналы.
- Эффекты попаданий.
- Вспышки контратак.
- Экран поражения.
- Экран результатов.
- Логотип игры.

Все игровые изображения должны быть пригодны для использования как самостоятельные ассеты. Фоны и персонажи не должны быть необратимо объединены в одно изображение.

# 18. Внутреннее меню разработчика

Для первой версии необходимо реализовать скрытое меню балансировки.

Оно не предназначено для обычного игрока.

Меню должно позволять изменять значения без редактирования исходного кода.

## Настраиваемые параметры

**Игрок**

- Максимальное здоровье.
- Максимальная выносливость.
- Стоимость ударов.
- Расход выносливости на блок.
- Скорость восстановления выносливости.
- Интервал между ударами.
- Дистанция поражения.

**Комбо**

- Время сохранения серии.
- Множители очков.
- Бонус третьего удара.
- Радиус поражения соседних врагов.

**Контратаки**

- Длительность предупреждения.
- Окно контратаки.
- Продолжительность оглушения.
- Бонус следующего удара.
- Бонус восстановления выносливости.

**Противники**

- Здоровье каждого типа.
- Скорость приближения.
- Частота атак.
- Урон.
- Скорость боковых перемещений.
- Длительность отшатывания.

**Уровень**

- Номер тестируемого столкновения.
- Состав и сложность волн.
- Скорость движения героя.
- Дистанции между встречами.
- Переход непосредственно к мини-боссу.

## Дополнительные возможности

- Сброс настроек к значениям по умолчанию.
- Перезапуск текущей схватки.
- Включение отображения зон поражения.
- Отображение дистанций до врагов.
- Отображение текущей цели.
- Просмотр текущего FPS.
- Временное включение неуязвимости для тестов.

Изменения параметров могут сохраняться локально для удобства повторных тестов.

Меню должно открываться только в режиме разработки либо через специальный скрытый переключатель.

# 19. Технические требования

## Платформа

Mobile Web, только вертикальная ориентация.

Целевые браузеры:

- Safari на iPhone.
- Chrome на Android.

Десктопный интерфейс не разрабатывается.

В десктопном браузере допускается тестирование внутри вертикального игрового окна.

При горизонтальной ориентации телефона показывается предложение повернуть устройство.

## Технологии

- Phaser 4.
- TypeScript.
- Vite.
- HTML5 Canvas/WebGL.
- Git для контроля версий.

Полноценный 3D-движок не требуется.

## Масштабирование

Базовое логическое разрешение — ориентировочно 360 × 640.

Необходимо адаптировать игровую область к смартфонам с разным соотношением сторон без искажения пиксельной графики и обрезания важной информации.

## Производительность

Целевой показатель — 60 FPS на современных мобильных устройствах.

Предусмотреть оптимизацию:

- Повторное использование игровых объектов.
- Текстурные атласы.
- Минимизацию лишних операций отрисовки.
- Разделение статичных и динамических элементов.
- Ограничение числа одновременно отображаемых частиц.
- Сортировку объектов по глубине.
- Корректную обработку паузы при сворачивании браузера.

Если целевые 60 FPS недостижимы на отдельном устройстве, важнее сохранить стабильность и корректность управления, чем визуальные эффекты.

# 22. Критерии готовности первого прототипа

Прототип считается играбельным, когда:

- Игра запускается локально в мобильном браузере.
- Интерфейс корректно работает в вертикальной ориентации.
- Дорожка создаёт убедительный эффект движения в псевдо-3D.
- Короткий тап вызывает ровно один удар.
- Удержание включает блок без случайного удара.
- Автонаведение корректно выбирает цели.
- Трёхударная комбинация работает по заданным правилам.
- Промахи, попадания, выносливость и комбо обрабатываются согласованно.
- Контратака прерывает удар и оглушает противника.
- Группы врагов динамически перестраиваются.
- Все 10 столкновений можно пройти.
- Контрольные точки работают.
- Повторное прохождение после поражения не позволяет бесконечно получать очки.
- Мини-босс использует две фазы.
- Добивание запускается автоматически.
- Итоговый рейтинг рассчитывается по очкам.
- Меню разработчика позволяет изменять параметры.
- При тестировании нет критических ошибок, блокирующих прохождение.
